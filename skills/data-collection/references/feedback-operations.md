# Feedback y operación

Las preferencias sobre qué resultados interesan necesitan ámbito, procedencia,
versión y forma de corregirse. No promuevas automáticamente una reacción a una
regla universal. Separa feedback de negocio de etiquetas Gold y de entradas de
conocimiento aprobadas; no activa entrenamiento ni publicación.

Si el fichero o almacén de feedback no se puede leer o validar, conserva el
original, informa el estado y usa solo un modo degradado autorizado que no lo
sobrescriba. Un reinicio o migración necesita una decisión explícita cuando pueda
perder preferencias; no añade esos cambios a Git de manera automática.

Para ejecución periódica, registra propietario, intervalo, presupuesto, cursor,
retención y cancelación. Un proceso sin nuevas entradas no tiene el mismo resultado
que una fuente caída. El resumen distingue capturados, normalizados, enriquecidos,
persistidos y fallidos sin contar el mismo ID como un éxito nuevo tras reintentar.

Valida en el consumidor fuentes vacías y malformadas, cambios de esquema, corte
durante paginación, IA desactivada, respuestas desordenadas, almacenamiento parcial
y reanudación. Son escenarios para el colector concreto, no evidencia de que esta
guía incluya un servicio funcionando.
