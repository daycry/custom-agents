## S050 — Caché por identidad del contenido de un archivo

**Identidad y lectura.** SHA-256
`c0242ee2fcb5c096d0625cb6957481fce2266e92985036795f5b5c13c329d802`;
5.732 bytes/162 líneas. Sin recursos locales; snippet, no biblioteca instalada.

**Contrato y valor.** Hash SHA-256 por chunks, entrada serializada, lectura
por clave, miss ante corrupción y wrapper de servicio separado del procesador.
Conserva rename/move con hit cuando el resultado solo depende del contenido,
opt-out de caché y logging acotado. Lookup por nombre no elimina el coste de
leer/hashear todo el archivo; no prometer O(1) para la operación completa.

**Correcciones.** Incluir versión de algoritmo/esquema y parámetros cuando
afectan al resultado; el propio cuerpo excluye ese caso en vez de resolverlo.
Separar resultado reutilizable de source_path actual para no atribuir un hit
al archivo antiguo. Leer el mismo snapshot para hash y procesamiento o
detectar cambios; dos lecturas independientes permiten guardar datos bajo
una clave de otros bytes.

Escritura directa JSON puede dejar archivos parciales con interrupción o
concurrencia. Definir validación de clave/ruta, writer atómico, concurrencia,
límites/evicción y permisos. Read puede fallar por encoding/IO además de JSON;
un miss solo cuando sea recuperable y sin ocultar el error del procesador.
Aplicar separación por proyecto/tenant cuando el contenido sea privado;
un hash no autoriza reutilizar datos entre identidades ni anonimiza el documento.

Frozen no implica que los objetos contenidos sean inmutables. El consejo
contra asdict por dataclasses congeladas es demasiado amplio: la
[documentación Python](https://docs.python.org/3/library/dataclasses.html)
admite recursión por dataclasses anidadas y deepcopy de otros objetos.
