# agent-kits/shared — fragmentos compartidos entre agentes

Fragmentos de prompt que usan **varios** agentes y que deben tener **una única fuente de verdad** (DRY). No es el kit de un agente concreto: es la excepción documentada a la regla «un kit por agente» (ver `docs/CONVENTIONS.md`).

| Fragmento | Qué contiene | Lo usan |
|-----------|--------------|---------|
| `estimation-defaults.md` | Parámetros de estimación (tarifa, supervisión, margen, FTE…) + regla de `.claude/rates.json` | `evaluator`, `planner` |
| `confluence-optin.md` | Paso «Sincronizar con Confluence (opt-in)» | `evaluator`, `planner`, `qa`, `documenter` |
| `ledger-lint.py` | Validación mecánica del ledger `tasks.md` (exit code; `--warn-only` para el hook); con `verificacion: obligatoria` en el frontmatter, una tarea sin `- **Verificación**:` es incoherencia dura (sin la clave: aviso solo si el ledger ya usa el campo — los ledgers legacy validan idéntico); expone `parse_ledger()` como módulo (campo `verificacion` por tarea) | `implementer`, `qa`, `/dev-cycle`, hook `ledger-lint-warn.sh`, `progress-report.py` |
| `progress-report.py` (+ tests) | Línea de progreso DETERMINISTA del ledger (`line`: `📋 slug · T-04/12 (33%) · fase 2/4 · en curso T-05 · IA real XhYm`), `active` (iniciativas en-progreso del roadmap), `session` (bloque ≤15 líneas de contexto de retoma), `--json`. Exit 0 siempre en `active`/`session`; nunca bloquea | hooks `progress-line.sh` / `subagent-progress.sh` / `session-context.sh`, `statusline/roadmap-statusline.sh` |
| `skill-index.py` (+ tests) | Índice COMPACTO y DETERMINISTA de las piezas del plugin (comandos con `argument-hint` compacto, skills, agentes) desde los frontmatters: 3 líneas de reglas de enrutado + una línea ≤ 110 caracteres por pieza (description recortada en la primera frase o en «Úsalo cuando»), ≤ 45 líneas / ≤ 3.500 caracteres (el ancho baja solo si hace falta). Caché por hash en `<proyecto>/.claude/.skill-index.cache` (`--no-cache`), `--json`; plugin localizado por `CLAUDE_PLUGIN_ROOT` → este kit → `find`. Desactivable con `dev.json` `sesion.indice: false`. Exit 0 siempre; sin piezas → sin salida | hook `session-context.sh` (SessionStart `startup|resume|compact`) |
| `journal.py` (+ tests) | **Journal de sesión** (memoria episódica, `docs/knowledge/journal/AAAA-MM-DD-<slug>.md`): `draft` (borrador DETERMINISTA sin modelo: fecha, iniciativa activa vía `progress-report.py`, ficheros tocados por git (top 10), tareas del ledger que cambiaron de estado vs HEAD, marcadores del meter cerrados hoy, primer prompt de la transcripción como resumen best-effort), `write` (idempotente por `session_id`: actualiza la entrada existente, sufijo `-2` si colisiona el nombre; regenera `journal/README.md`; `--enrich` para decisiones/pendientes manuales), `latest --n 2 --max-lines 25` (bloque compacto para el contexto de sesión), `index`. Exit 0 siempre salvo uso (2); sin git degrada con aviso | hooks `session-journal.sh` (SessionEnd) y `session-context.sh` (SessionStart `startup\|resume`); `/retro` (causas de desviación); lectura acotada en `knowledge-check.md` |
| `model-tier.py` (+ tests) | Tier EFECTIVO de un agente (`model` + `effort`) en dos capas: frontmatter de `agents/<agente>.md` + override parcial por agente en `.claude/dev.json` `modelos` (valor inválido → aviso y se ignora; fichero ausente/corrupto → frontmatter). `<agente> [--json]` o `--all` (tabla). Exit 0 · 1 agente inexistente · 2 plugin no localizado. El `effort` de dev.json se declara INFORMATIVO (el Agent tool no lo admite por invocación; sub-agents.md 2026-09-03) | `/dev-cycle`, `/pm-cycle`, skill `adversarial-review` (lentes → `reviewer`), `quick-implement`, `/setup` 5-quater |
| `rationalization-table.md` | Formato y reglas de la **tabla de racionalización** (patrón «iron law»): cabecera exacta `| Excusa que el modelo se da | Por qué no vale | Qué hacer en su lugar |`, 6-8 filas en primera persona y entrecomilladas, cada fila cierra con la acción concreta, colocada JUSTO ANTES del DoD/veredicto, ≤ 25 líneas, sustituye la prosa equivalente. Lo valida `tests/test_rationalization_tables.py` | `implementer` (antes del DoD), skill `adversarial-review` (antes de «6. Salida y traza»), `qa` (antes del DoD); toda pieza nueva con DoD/veredicto (`plugin-dev`) |
| `docs-style.md` · `docs-style.en.md` | Guía de **redacción técnica** (8 reglas con señal y antes/después: frases cortas, voz activa, un concepto por párrafo, tablas para comparar y prosa para explicar, ejemplos reales del código, sin adjetivos vacíos, títulos que responden preguntas, bilingüe sin traducción literal). Criterio de revisión solo cuando es citable (regla + línea) | `documenter`, `analyst`, `planner`, `architect` (al redactar); Lente A de `adversarial-review` SOLO en iniciativas de prosa |

| `personas/` (6 perfiles) | Catálogo CORTO de personas de dominio (`frontend` · `backend` · `db` · `devops` · `test` · `docs`): prioridades, trampas típicas, calidad y evidencia exigibles de cada dominio (~10 líneas cada una — corto por diseño, para que se mantenga). `task-brief.py` antepone la persona al brief cuando la tarea lleva `- **Tipo**: <tipo>`; sin etiqueta → genérico (sin aviso: el campo es opcional); etiqueta sin persona en el catálogo → genérico CON aviso (degradación) | `task-brief.py` (iniciativa subagent-personas) |

Resolución en runtime (igual que el resto de kits):

```bash
SHAREDKIT="$(find "$PWD/.claude" "$HOME/.claude" -type d -path '*agent-kits/shared' 2>/dev/null | head -1)"
```

Si un agente no encuentra el fragmento (instalación parcial), usa el fallback de una línea indicado en su propio prompt; no inventa valores nuevos.

**Portabilidad (distribution T-01).** `scripts/export-skills.py` copia al paquete portable «solo skills» SOLO los fragmentos de esta carpeta que las skills citan (`agent-kits/shared/<x>` o `$SHAREDKIT/<x>` en su texto, con cierre: `scope-check.py` arrastra `ledger-lint.py`, `knowledge-write.md` arrastra `templates/`), conservando la ruta `agent-kits/shared/` para que los `-path '*agent-kits/shared/…'` sigan casando. Si añades aquí un fichero que una skill necesita, cítalo por su ruta en la skill (así viaja); lo que solo usan agentes no viaja y no hace falta que lo haga.

La tabla de **transiciones de estado** de la cadena spec→evaluación→plan NO vive aquí: su única fuente es la **regla 7 de `docs/CONVENTIONS.md`** (los commands remiten a ella).
